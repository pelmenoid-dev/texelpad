# Texelpad

## Platform
Desktop-first local web app. Isolated beside the Unity solution, outside Assets, Packages and ProjectSettings.

## Users and purpose
A Unity artist paints hand-painted pixel materials directly on a UV-mapped model and exports original or processed maps.

## Capabilities and constraints
- OBJ and FBX with existing UVs. No STL.
- One diffuse/spec/glow set for the whole model.
- Diffuse JPEG or PNG with alpha; spec and glow are grayscale intensity maps.
- Pencil and brush, adjustable size, undo/redo, direct 3D and texture-preview painting. Both surfaces share tools, opacity, hardness, map selection, color picking and history. Preview painting also works without a model and uses the GPU with a CPU fallback. The UV button at the bottom-left of the preview toggles a contrasting triangle-edge overlay; painting works with the overlay on or off. UV visibility is saved in projects, defaults to off, and never enters map pixels or exports.
- Each project has separate palettes for Diffuse, Specular and Glow. A single click selects a saved color for painting; double-click, long-press, right-click or F2 opens its picker popover for editing; + opens a new-color popover with explicit Add color. The Diffuse popover includes hue, saturation/brightness and HEX; Specular and Glow use a black-to-white slider and percentage. All three include the same compact eyedropper and removal action. Palette edits do not recolor painted textures. Duplicate colors cannot be committed; up to 256 colors retain their order in .pxwork. New projects start with 11 editable Diffuse colors: three neutrals and eight muted colors, including the default warm brush color. Each of Specular and Glow starts with five grayscale swatches. Replacing a model resets palettes to these defaults; the first model import preserves the prepared project palette. Saved custom or explicitly empty palettes stay exact. When an older project has no Diffuse palette field, opening it derives up to 11 representative colors from the original Diffuse pixels. Fully transparent pixels are ignored, coverage is weighted by alpha, and close shades share a swatch. Recovered swatches use actual source colors, are editable and are saved normally; source maps, painting history, grayscale palettes and the current brush stay unchanged. A fully transparent Diffuse map yields an empty palette.
- Live studio lighting, specular highlights, emission and diffuse alpha. Neutral studio reflections have a broad, smoothly fading profile; curved surfaces should not mirror hard rectangular panel edges. The specular mask controls strength, with black disabling the reflection. This is the fixed studio look, not a separate roughness map or control.
- Render offers a Lighting switch: on is Lit, off is Unlit. Unlit shows diffuse color and alpha without lights, specular reflections, emission, bloom, shadows or the lighting tone curve; shared-grid sampling and dithering remain active. Projects save the mode, and older files default to Lit. Lighting controls keep their values and stay visible but disabled in Unlit, matching the Pixelisation switch behavior.
- Shared texture grid for all maps, derived from diffuse dimensions and texels per pixel. Apply color quantization and centered Bayer 8x8 dithering independently to Diffuse, Specular and Glow before lighting. Diffuse uses encoded sRGB channels; masks use linear intensity. Color levels counts levels per channel including black and white; zero Dithering keeps nearest-level quantization. Alpha is sampled but never quantized. At 256 levels, all existing 8-bit colors remain exact.
- Model textures, map previews and Pixel grid PNGs use the same processed pixels, including during GPU painting. Original PNGs keep source colors and resolution. Projects retain editable sources and processing settings, so processing is reversible after reopening. SurfacePixels luminance roll-off stays in the material after lighting; there is no second dither pass. Export metadata describes pre-light texture processing and disables the old Unity after-lighting dither.
- Nondestructive processing; export edited source maps or processed maps. The only Pixelisation switch sits beside the Pixelisation heading in Render and controls the model and all map previews together. Turning it off disables the grid and dithering controls without changing their values. Saved projects retain the shared enabled state; older files use their material processing state instead of the retired independent map-preview preference.
- Brush coverage clips the square texel footprint against UV triangles and samples inside that overlap, keeping visibility rays off adjacent face edges at concave seams. Collapsed UV triangles cannot paint unrelated pixels. Hidden surfaces still require another camera angle or direct texture painting. Grid-aware padding extends color and alpha into unused UV gutters for preview and both exports; island contents and editable buffers stay intact. Very coarse grids can still merge nearby islands into one cell.
- Files stay on this device. A .pxwork project embeds normalized model geometry, exact editable RGBA maps, both undo/redo stacks, processing and lighting settings, brush/tool/map selection, camera and panel state. It opens without the original FBX/OBJ or textures.
- Save project (Ctrl+S) and Open project (Ctrl+O) live in the compact Project menu alongside New project. Startup and New project use an empty Untitled document; New project confirms before discarding unsaved work. Model-free projects retain textures, palettes and settings through save/open and their first model import. Texture ZIP export remains a direct top-bar action. Undo and Redo live in Edit immediately after Project, retaining their keyboard shortcuts and history-dependent disabled states. The model follows Edit in the common top bar: the filename opens a menu with its full name, triangle count and Replace model. Empty projects show a direct Load model button. On mobile this model control occupies the second top-bar row. Corrupt/unsupported projects leave current work intact; cancelling or failing a save keeps unsaved work marked.
- The entire interface is in English, including tooltips, import errors, confirmation dialogs and export controls.
- The left painting panel starts directly with Diffuse / Specular / Glow tabs. A permanent Render panel of equal width sits to the right of the studio; both panels are available together without an opening button or mode switch. A large square live texture preview fills the panel width below the tabs; rectangular maps fit without stretching. A compact Load texture button in the neutral Load model style overlays the top-left corner, and the displayed map dimensions appear on a translucent dark text badge in the top-right corner (processed dimensions while Pixelisation is on, original dimensions while it is off). The preview is always visible and directly paintable, with no popup. Brush controls follow, with Color at the same level as Size, Opacity and Hardness (Color is hidden for Eraser). Render contains two matching sections: Pixelisation and Lighting, each with a heading switch and parameters below. Disabled effects retain their settings, visible but inactive. Desktop panels scroll independently; the left map tabs stay fixed, and the right panel has no separate title row. Mobile stacks both panels in a scrolling workspace beneath the sticky studio. Projects preserve the selected map; legacy preview visibility and Paint / Render preferences are accepted but no longer affect the layout. All maps use the Color field with the same selection and editing gestures; Specular / Glow restrict swatches to grayscale, with intensity controls inside the popover.
- Render groups lighting and material controls. The viewport's bottom-right Wireframe toggle shows the model's triangle edges over the painted surface and persists in projects. It starts off; the floor grid remains visible in quiet gray over a light gray viewport background. Wireframe helpers do not enter editable geometry, texture exports or project model data. The editor has no permanent bottom status strip, shortcut legend or standalone help button.

## Brand commitments
Simple, pleasant, low-fi, almost toy-like UI inspired by Aseprite. The editing canvas leads, with compact tools and a readable palette.

## Stack and workflow
User confirmed React + Three.js, local operation, and building the working editor directly without a separate visual comp. Radix primitives follow the shadcn composition; Motion handles export-panel state transitions.
